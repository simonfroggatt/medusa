# Medusa — Django back office for Total Safety Group

**Read `/Users/simonfroggatt/Development/tsg_medusa/CLAUDE.md` first** (shared DB, tsg_store integration, cross-repo rules), then `…/tsg_medusa/docs/medusa_app_map.md` for the full per-app map. This file is the short Medusa-only version.

- Django 4.2.7 + DRF, Bootstrap 5 / crispy forms / django-bootstrap-modal-forms / jQuery / DataTables. MariaDB via `DB_*` env vars (names only). Settings `medusa/settings.py` (local, git-ignored; `settings_remote.py` = lagging manual copy of prod). Venv is **`.venv1/`** (`.venv/` is an empty leftover). Run: `.venv1/bin/python manage.py runserver` → `127.0.0.1:8000` (tsg_store's local `TSG_MEDUSA_URL`).
- Layout: `medusa/` = shared core (tax classes/rates, language, country ISO, payment terms, account types, supplier, file types, order-product status, compliance standards, `auth_user` shadow; plus `decorators.py`, `services.py`, templatetags). Domain apps in `apps/`: products, options, symbols, category, pricing, bulk, customer, company, suppliers, orders, cart, quotes, returns, shipping, bespoke, paperwork (PDFs), emails (Gmail API), templating, pages, sites (stores/currencies), dashboard, feeds, xero_api, authentication; `payments` dormant; `purchases` UI unused but imported by orders — don't break it.
- **All `oc_*`/`oc_tsg_*` models are `managed=False` and no app has migrations.** Table changes = hand-written SQL for Simon in `sql/YYYY-MM-DD_<name>.sql` (preview / execute / verify), then update the model. Many tables **do** have real FK constraints (check `SHOW CREATE TABLE`) — insert parents first. Multiple apps may map one table — trace usage before touching a shared model; don't dedupe.
- Tests: `SimpleTestCase` + unsaved model instances + `mock.patch` (no test DB for `managed=False` tables). Examples: `apps/emails/tests.py`, `apps/orders/tests.py`. Run `.venv1/bin/python manage.py test apps.emails apps.orders`.
- Dominant pattern: function-based views; modal forms return `JsonResponse({'html_form', 'form_is_valid'})`; DRF `ModelViewSet`s serve DataTables. Model new work on `apps/shipping` (cleanest, 2026). Status ids are hard-coded across apps and history rows are written from `save()` overrides — keep consistent with existing values (read them from the DB), don't invent new ones.
- Endpoints hit by tsg_store (all `@csrf_exempt`, `order_hash`-protected): `bespoke/api/convert-order/<id>`, `xero_api/api/order/add/<id>/<hash>`, `paperwork/webstore_pdf[_view]/<id>/<hash>`. Changing their URL or response shape breaks checkout.
- View-level auth is sparse (few `@login_required`, DRF AllowAny) — don't assume a new view is private; ask Simon what protection is expected. Admin-only tools use `@group_required('superuser')` on the view plus `{% if request.user|has_group:"superuser" %}` (`{% load user_tags %}`) in the template.
- New inter-app logic: call services/functions directly. Do not copy the `_push_to_xero` self-HTTP pattern.
- Never commit `client_secret.json`, `gdrive.json`, `token.json`, `db.sqlite3`, `logs/`, `tmp/`, `tmp_models.py` — check `.gitignore` before staging.
